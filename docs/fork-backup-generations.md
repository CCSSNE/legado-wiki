# Fork 备份分支换代与状态记录

每个项目保留一个 `legado-backup/legado-<id>` 仓库。原有默认分支作为第一代；历史无法快进时，创建 `backup/v<代数>-<上游完整 SHA>`，旧分支永不修改或删除。完整 SHA 用于在创建成功、状态保存失败的情况下识别并复用同一分支。

## 处理规则

- 正常追加：验证历史关系后，以 `force: false` 快进当前同步分支。
- 分叉／无共同祖先：重新读取双方 HEAD 并再次比较，确认一致后创建下一代分支；核对新分支 SHA，再记录当前分支和旧分支，最后切换备份默认分支。
- 仓库改名／转移：按备份 parent 的仓库 ID 或已记录的上游 ID 查询；只有 ID 一致才跟随，名称被其他仓库占用不改变原上游身份。
- 默认分支改名／原分支被删除：读取当前上游默认分支，历史仍可衔接就继续使用当前备份分支，否则换代。上游分支名称与备份分支名称无需一致。
- 上游不可见：永远继续每轮探测。404 无法区分删库、私有化和权限不足，报错并记录；410 记为上游不可见而不停止探测。恢复后自动同步并记录恢复事件。
- 网络超时、限流、500、权限错误：GET 有 30 秒超时，临时网络及 429/5xx 最多重试三次；失败让 Action 报红，保留所有备份。不把普通 404 误判为无共同祖先。
- 只有名单移除、`skipAutoForks` 或 `backupRelease` 等人工配置才退出 Fork 同步。镜像项目继续使用独立镜像工作流。

## 状态与通知

`data/fork-sync.json` 保存当前上游身份、备份当前分支、代数、旧分支记录，以及各仓库状态变化的完整事件列表。`backup-status.html` 展示当前状态与历史记录，时间使用北京时间；重复相同状态不重复记录，恢复、改名、换代单独记录。

状态记录从此改动上线后开始，不伪造以前发生时间。首次运行发现既有历史分叉时会自动建立第二代。

正常轮询不发通知；自动换代、识别改名或恢复时通知一次。失败仍发错误告警，邮件不代替 Action 失败状态。

工作流按顺序执行，禁止同一同步工作流并发。状态只在验证成功后更新，写入失败报错；提交状态时遇到其他数据工作流的提交，fetch/rebase 后重试推送。脚本不使用强推、不归档整个仓库，也不创建每代独立仓库。

## 验证

运行 `node --test tests/fork-sync.test.mjs`。覆盖快进、分叉、无共同祖先、改名、临时不可见与恢复、连接失败、权限失败、创建失败、异常期间上游变化、中途失败后的分支复用及日志去重。
