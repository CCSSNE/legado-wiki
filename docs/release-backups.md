# Release 自动备份

GitHub Fork 只同步代码，不会复制上游的 Release 说明和下载附件。`Release 附件备份` 工作流每小时独立运行，使用现有 `FORK_TOKEN`，将 `data/fork-sync.json` 中已建立备份的 GitHub 上游的公开 Release（含预发布版）保存到对应的 `legado-backup` 仓库。

## 保存内容

- 原发布说明、名称、预发布属性，以及原始时间与来源信息。
- 每个 Release 的全部上传附件，不筛选扩展名，下载和上传均校验大小与 SHA256。
- 固定到当时提交的独立标签 `backup-release/<release-id>-<内容指纹>`。附注标签解析到提交；GitHub 自动提供该提交的源码 zip/tar 下载。
- 附件中的 JSON 来源清单，记录原标签对象、原发布元数据及附件对应关系。

说明、附件、发布时间或标签对象发生变化时会建立新快照。已发布的备份不覆盖、不删除。上游删除或隐藏发布之后，已保存的快照仍保留。标签消失、仓库不可见、网络或权限失败会记录异常并使 Action 失败，下次继续探测。备份不主动停止。

## 补档与恢复

首次运行先保存每个上游最新的发布，再逐轮补齐当前仍可访问的历史发布。每轮最多完成 8 个快照，每个上游最多一个，起点轮换；20 分钟后不启动新的附件传输。大附件传输有单次超时，工作流总超时为 45 分钟。

附件全部校验通过、来源清单成功上传后才发布备份。中途失败保持为草稿，下一轮复用已验证的附件继续传输。进度与异常历史保存在 `data/release-sync.json`，并展示在“备份同步状态”页面。两站点均读取随主分支发布的同一份数据。

这里的范围是已经加入 Fork 备份的 GitHub 仓库；人工跳过的补档仓、非 GitHub 镜像及未公开的草稿不自动纳入。此前已被上游删除且没有其他存档的附件无法追溯恢复。代码备份与 Release 备份是独立任务，页面分别显示状态。
